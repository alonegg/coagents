# CoAgents 使用场景

版本：0.2 · 日期：2026-09-23 · 状态：产品设计场景，人物与项目均为示例，不是真实访谈或用户证据。

场景依据 [PRD](PRD.md) 编写，全部属于第一版。核心场景从 S-09 多人分布协作开始；原场景编号保留以维持引用。同机使用是兼容情境，不能替代跨设备验收。操作细节见 [Use Cases](USE_CASES.md)。

## S-09 多人分布协作：每个人用自己的电脑与 Agent

**人物与背景**：林作为 Owner 部署团队服务，陈作为 Contributor 在另一地点开发，周作为 Viewer 在自己的浏览器审阅。林和陈各自运行不同编码客户端，使用独立账户和设备授权。

**触发**：团队希望分工开发同一项目，实时知道彼此在做什么并能接手工作。

**过程**：林创建项目、里程碑和任务，分享有限期邀请。陈注册/登录并接受邀请，在自己电脑授权 Connector 和 Agent。两边读取同一决策并认领不同任务，Hub 实时显示业务变化。陈交接代码任务时记录仓库与 commit，林在自己的工作副本校验材料后接手。成果发布后，周用 Viewer 权限阅读和全文检索；Owner 完成验收与里程碑确认。

**用户看到的内容**：每条活动有用户、设备和 Agent 来源；连接状态与任务状态分开。成果内容从团队存储读取，不依赖陈电脑上的绝对路径。定向提醒有送达/读取状态，不声称自动启动了对方 Agent。

**失败处理**：陈断网时不能获得新的有效租约，界面标注未同步；重连检查权限并补读事件。林缺少指定 commit 时，交接保持待处理。管理员撤销设备后，已有连接停止接收事件。

**成功判据**：三账户、两台独立机器、两种真实客户端跑通完整流程；在 LAN 和一种跨网络路径完成验证；包含并发认领、断线恢复、成果检索及受限内容不泄露的证据。关联 UC-01 至 UC-22，重点 UC-12、UC-17、UC-18、UC-19、UC-22。

## S-01 一个人同时使用两个编码 Agent

**人物与背景**：林是独立开发者，在同一台电脑上用两个编码客户端开发一个应用。一个负责界面，一个负责服务接口。两边都有独立会话，容易出现重复开发和不同的接口假设。

**触发**：林准备把一个较大的功能拆开并行推进。

**过程**：林在 Hub 创建项目，写明目标和关键约束，将工作拆成两张带验收条件的任务卡，并分别授权两个客户端连接。两个 Agent 读取同一份当前决策，认领不同任务。若同时认领一张卡，只有一个成功，另一个得到占用说明。界面 Agent 提交说明和预览链接，接口 Agent 提交测试结果与 commit 信息，任务进入待验收。

**用户看到的内容**：Hub 同时显示两张卡的执行者、租约和状态；每张卡都能打开提交材料。林验证结果后接受任务，完成计数随之变化。

**价值与边界**：减少重复认领，让结果有统一入口；租约不会锁住工作目录，也不会阻止不使用 CoAgents 的进程改文件。Git 分支和文件分工仍需要开发者安排。

**成功判据**：两个客户端实际读到相同项目上下文；没有双有效持有者；可从已完成卡片找到验收依据。关联 UC-01、UC-04、UC-05、UC-08、UC-09。

## S-02 负责人每天查看多个项目

**人物与背景**：周负责“教学网站”“数据工具”“文档工作台”三个项目，不想逐个打开客户端聊天找进度。

**触发**：一天开始时，需要判断先处理哪个项目。

**过程**：周登录 Hub，看到本人有权限的活跃项目。教学网站有两项待验收，数据工具有一个阻塞，文档工作台没有新业务活动。周筛选阻塞事件，进入关联任务读取缺少数据的原因；补充一条项目决策后，再打开待验收成果。

**用户看到的内容**：项目卡片给出最近可见活动、五列任务数量与最近成果。跨项目活动流能进入具体任务。Agent 显示在线时，项目不会因此被标记为“进展顺利”。

**价值与边界**：负责人能定位需要自己介入的事项。任务完成比例只是任务计数，不能比较不同项目的工作量或质量。

**成功判据**：无权项目不出现在卡片、搜索或统计里；阻塞能追到具体任务；没有任务的项目显示“暂无任务”。关联 UC-02、UC-03、UC-06、UC-09。

## S-03 工作阻塞后更新项目决策

**人物与背景**：一个 Agent 按旧接口说明推进任务，发现依赖数据尚未准备好。

**触发**：继续开发需要负责人决定采用模拟数据还是等待真实数据。

**过程**：Agent 提交阻塞原因并关联任务，任务进入阻塞且释放执行租约。负责人在 Hub 阅读问题，发布采用固定模拟数据的决策，明确它替代此前的“必须使用真实数据”要求。Agent 再次读取上下文，看到新决策和旧决策已被替代，重新认领任务。

**用户看到的内容**：时间线包含阻塞、决策更新和重新认领；当前决策区只显示有效版本，旧版本可追溯。

**失败处理**：若两个人同时替代同一决策，后提交者收到冲突提示并查看最新版本；系统不能同时默认为两条互斥决策均有效。

**成功判据**：变更没有丢失历史；阻塞与任务一致；读取事件不会自动执行同伴正文中的命令。关联 UC-06、UC-14。

## S-04 将已经做出的报告纳入项目成果

**人物与背景**：项目开始使用 CoAgents 前，已经有 Markdown 调研报告、PDF 和在线原型链接。

**触发**：负责人希望团队能在 Hub 查看已有工作，不再到不同文件夹寻找。

**过程**：贡献者选择目标项目，逐项导入文件或填写链接，补充标题、原始作者和已知的原始日期。材料先成为草稿。贡献者检查 Markdown 正文与文件后发布；需要限制范围的材料先由管理员配置可见名单。

**用户看到的内容**：成果列表显示类型、作者、来源、发布版本和相关任务。已发布文件保存在受管存储中，即使原导入路径变化，授权下载仍能工作。

**失败处理**：未知原始日期显示“未知”；无法预览的类型提供下载；上传中断不显示已发布成功。外部链接失效时，原链接记录仍存在，但系统不声称内容已被保存。

**成功判据**：能直接阅读正文或打开文件；创建时间与导入时间不混淆；受限资料不会经由首页活动泄露标题。关联 UC-07、UC-08、UC-10、UC-11。

## S-05 审阅成果并要求修改

**人物与背景**：贡献者提交了一份方案说明，项目 Owner 需要判断是否满足任务中的验收条件。

**触发**：任务进入待验收。

**过程**：Owner 打开任务，查看完成说明、提交时绑定的成果版本和验收条件，发现缺少验证记录，于是写明原因并退回待办。贡献者重新认领，修改成果形成新的草稿并发布下一版本，再次提交待验收。Owner 接受后任务变为已完成。

**用户看到的内容**：成果发布和任务接受是两个不同动作；任务保留每次提交、退回原因、证据版本和接受人。旧版本不会被新文本覆盖。

**失败处理**：如果引用成果对验收人已不可读，系统提示先处理访问范围；如果页面上的任务版本已过期，验收操作不覆盖新的状态。

**成功判据**：仅发布成果不会增加完成计数；接受后可追到当时验收的版本。关联 UC-08、UC-09、UC-10。

## S-06 给只读审阅者一个受控入口

**人物与背景**：项目需要让评审账户查看进度和部分已发布材料。该账户不参与开发，也不应读到工作草稿或内部预算材料。

**触发**：Owner 邀请本实例的一个已有账户作为 Viewer。

**过程**：账户接受邀请后进入项目，可以查看看板和普通已发布成果。预算成果的受限名单不包含该账户，因此列表、搜索、活动和文件下载都不可见。Owner 需要开放某项材料时，显式调整名单。

**用户看到的内容**：Viewer 的界面提供阅读与下载入口，任务编辑、发布和成员管理入口不可用。

**部署方式**：评审者在自己的电脑通过受保护的服务地址登录；用真实 Viewer 账户验证附件、搜索和实时活动权限。

**成功判据**：粘贴附件直链不能绕过权限；无权成果不会以标题或统计差额暴露。关联 UC-11、UC-12。

## S-07 Agent 会话中断后的接手

**人物与背景**：负责某任务的 Agent 会话准备结束，另一个同机或远程会话需要接着处理。

**触发**：原执行者主动交接，或租约已经过期。

**过程**：主动交接时记录已经完成的内容、下一步、已知风险和本机工作位置的说明，关联成果或 commit，然后释放租约。接收者读取交接，跨设备时核对仓库、所需 commit 和成果版本，确认材料可用后再原子认领。若旧会话意外退出，Hub 标注租约已过期；接收者只能根据最后已保存的记录接手，不会看到虚构的交接总结。

**用户看到的内容**：任务状态与租约状态分别呈现；记录原持有者和新持有者。旧会话恢复后不能用过期租约修改任务状态。

**成功判据**：接手有新的有效租约；中断不会自动标记任务完成；说明中不包含自动执行指令。关联 UC-05、UC-14、UC-15。

## S-08 撤销成员并归档项目

**人物与背景**：项目阶段结束，需要收回某个贡献者及其 Agent 的访问，并保留可审阅的历史成果。

**触发**：Owner 决定结束协作。

**过程**：Owner 移除成员，该成员的新请求立即失效，关联 Agent 连接也失去项目权限。其他成员仍可查看授权成果。随后 Owner 归档项目，所有任务和成果写入停止，项目从默认活跃列表移到归档筛选中。

**用户看到的内容**：管理员能从审计记录查到撤销与归档操作；普通成员看到只读状态。恢复项目后只恢复正常业务读写，不恢复此前移除的成员或已撤销的凭证。

**边界**：收回访问不会删除对方此前合法下载的文件，也不会中止不受 CoAgents 控制的本地 Agent 进程。

**成功判据**：已登录会话、附件直链和 MCP 后续请求都受最新权限约束。关联 UC-12、UC-13、UC-16。

## S-10 团队围绕里程碑和截止日期推进

**人物与背景**：负责人需要在一个日期前交付可演示版本，贡献者分布在不同时区。

**触发**：Owner 创建“可演示版本”里程碑，设定验收条件、目标日期与关联任务。

**过程**：Hub 按项目时区解释日期，并按各用户时区显示准确截止时间。贡献者提交任务后，里程碑同时展示已完成、阻塞、待验收数量。目标日期已过且尚未达成时标记逾期；负责人检查成果、调整确有变化的范围并记录理由，最后明确确认达成。

**失败处理**：到期不自动完成；任务数为零不显示 100%；未完成任务不能被悄悄移出以制造达成。里程碑调整通过实时事件通知成员。

**成功判据**：不同设备看到同一截止时刻，数量与任务板一致；范围变更和达成依据可追溯。关联 UC-20。

## S-11 从历史成果正文找回已有结论

**人物与背景**：陈记得项目曾讨论一项技术选择，但不知道报告标题，也没有那份文件的本机副本。

**触发**：在 Hub 输入正文关键词并限定项目。

**过程**：系统在陈有权限的已发布 Markdown、纯文本和有文本层的 PDF 中检索，展示命中片段与版本，点击可定位到正文或文档页。查看旧版本时显示版本标识，避免把旧结论当作当前结论。

**失败处理**：扫描件或不能提取的文件明确标记检索限制；新成果未索引显示处理中。Owner 收紧权限后，即使索引尚未物理清理，陈也不能再从摘要、数量或缓存读到该成果。

**成功判据**：用仅存在正文的词能检索到授权文件；同一关键词对无权账户不泄露结果或片段。关联 UC-21。

## S-12 断网和成员撤权时保持一致

**人物与背景**：贡献者临时断网，Owner 在这段时间调整了任务或撤销其设备。

**触发**：设备重连，同时 Hub 原有推送连接和 Connector 尝试恢复。

**过程**：客户端先验证身份和设备状态，再检查任务版本及租约；有效连接按最后确认事件补读。响应丢失的写入使用原请求标识查询结果，不能生成重复成果。权限失效时停止推送、读取和写入，保留本机未提交输入并提示重新授权。

**边界**：无法远程收回此前下载的副本，也不声称能终止其他客户端独立运行的进程。

**成功判据**：没有双持有者、丢失的持久化事件或重复发布；被撤销设备在旧长连接、全文检索和附件路径上都不能继续获得新内容。关联 UC-15、UC-18、UC-22。
