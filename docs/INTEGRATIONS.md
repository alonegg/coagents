# 客户端集成策略

状态：拟议。支持范围只按实际测试结果公布。

## 首版集成方式

优先使用客户端公开支持的 stdio MCP 配置。每个适配器需实现检测、配置差异预览、写入、重复执行、卸载和真实启动验证。不能仅凭配置文件存在就标记“已支持”。

每个成员在自己的设备运行 Connector，填写同一团队服务地址并完成登录与设备授权。Connector 经 HTTPS 访问服务，校验证书，持久化事件游标并在断线后重新授权和补读。浏览器与 Agent 连接使用各自会话，不能把人的会话凭证交给 Agent 代行管理或验收。

集成层用统一接口表示：`detect()`、`preview()`、`install()`、`verify()`、`remove()`。每个客户端的路径、配置格式和 Hook 能力单独维护版本说明；不要将某一客户端的内部配置规则套用到其他客户端。

## 配置写入规则

- 默认只修改用户明确选择的客户端和项目级配置。
- 保留原有字段、顺序与手写内容；写入前创建本地备份，采用原子替换。
- 只删除本产品明确标记且仍匹配安装时内容的条目；用户后来改动的内容不自动覆盖。
- MCP server 标识、可执行路径、状态目录和生成的注释使用 CoAgents 命名；技术标识暂定为 `coagents`，由统一配置生成。
- 不在示例或生成配置里引用第三方安装脚本、服务端或包。

## Hooks 与回退

Hooks 是可选增强，不作为首版基础能力的前置条件。若某客户端不支持 MCP，可另行设计本地 CLI 回退，但 CLI 参数必须以 argv 数组传递，不拼接 shell 命令。任何自动注入给 Agent 的同伴内容都应标记来源并视为不可信。

Agent 连接必须绑定用户、设备和单个项目，凭证可撤销；MCP 调用与 Hub 操作经过相同的服务端权限检查。配置预览不得展示凭证原文，卸载时撤销对应凭证。设备或成员被撤销后，已有事件通道不能继续收内容，断线前的过期租约不能重放。

Connector 可接收实时事件及定向交接，Agent 是否立即读取取决于客户端的实际能力；送达和读取分别记录。Git 交接仅在用户选定目录做明确检查，不从同伴文本构造命令。

## 验收记录模板

每个适配器记录客户端版本、操作系统、实际设备、服务地址类型、安装前后差异、真实工具调用、实时收取与重连、Git 交接、撤销及卸载结果。至少两台独立机器、两种客户端联测；没有记录时保持“待验证”。
