# CoAgents User Stories 与 Use Cases

版本：0.2 · 日期：2026-09-23 · 状态：P0 验收用例草案，尚未执行。

本文包含 User Story、参与者、触发条件、主流程、异常和验收条件。业务规则以 [PRD](PRD.md) 为准，人物情境见 [使用场景](SCENARIOS.md)。所有测试应分别覆盖 Hub 和相应的 MCP/API；隐藏按钮不能替代授权测试。

## UC-01 首次设置、登录与创建项目

**User Story**：作为项目创建者，我希望建立个人身份并创建一个私有项目，以便开始保存协作记录。

**参与者与前提**：实例维护者、项目创建者；团队服务已部署并可经受保护地址访问。**触发**：首次打开 Hub，或已登录用户选择“创建项目”。

**主流程**：

1. 首次设置建立维护账户；成员通过有效邀请注册或由维护者建账户，不开放无邀请注册。
2. 用户登录，输入项目名称、目标和说明。
3. 系统创建活跃私有项目，将创建者设为唯一 Owner，打开项目概览。
4. 用户可创建任务或设置 Agent 连接；退出时会话失效。

**异常与恢复**：重复提交不创建两个项目；输入无效时保留内容并指出字段；服务写入失败时不进入虚假的项目页；已有实例不能再次未经认证取得维护身份。

**验收**：Given 未登录身份，When 请求项目数据，Then 不返回内容。Given 创建请求重试，Then 只有一个项目和一个 Owner。Given 已退出，Then 旧会话下一请求被拒绝。

关联：FR-01、FR-02；S-01。

## UC-02 查看我的项目和项目概览

**User Story**：作为负责人，我希望看到我能访问的活跃项目及其任务、活动和成果概况，以便决定先处理什么。

**参与者与前提**：任意已登录项目成员。**触发**：打开 Hub。

**主流程**：

1. 系统查询当前身份的有效成员关系，列出活跃项目。
2. 用户按名称查找或按最近可见活动排序；需要历史项目时选择归档筛选。
3. 项目卡片显示五列任务数、最近可见活动、最近可见成果。
4. 用户打开项目概览，再进入阻塞任务、待验收任务或成果详情。

**异常与恢复**：无项目显示可用操作；加载失败显示失败状态而非零项目；卡片点击时成员权限已撤销，进入不可访问提示。

**验收**：Given A 属于两个项目、B 只属于一个，Then B 的列表、搜索和总数不包含另一个项目；空任务集不显示完成百分比。

关联：FR-03；S-02。

## UC-03 阅读和筛选项目活动

**User Story**：作为项目成员，我希望按项目、类型和操作者阅读变化，并进入关联内容，以便知道发生了什么。

**参与者与前提**：已登录成员，已有业务事件。**触发**：打开跨项目或项目内活动。

**主流程**：

1. 系统按权限筛选事件，以时间倒序展示。
2. 用户选择项目、事件类型或操作者，继续翻页。
3. 用户点击事件，进入可访问的任务、决策或成果版本。
4. 用户刷新获取新事件；界面显示最后同步时间。

**异常与恢复**：过滤后没有事件显示“暂无活动”；连接中断保留旧内容和时间标识；目标权限变化后不继续展示缓存摘要。心跳和后台轮询不产生业务活动。

**验收**：Given 受限成果发布事件，When 无权成员查询活动及分页总数，Then 不出现该事件及其摘要；新增事件后翻页不会造成永久漏读。

关联：FR-04、FR-15；S-02、S-03。

## UC-04 创建任务并更新 Kanban

**User Story**：作为贡献者，我希望用任务明确工作内容和验收条件，以便大家理解分工并查看进度。

**参与者与前提**：Owner/Admin/Contributor；项目活跃。**触发**：创建任务或打开任务详情。

**主流程**：

1. 用户输入标题、说明、验收条件和可选负责人，任务进入待办。
2. 系统记录任务创建事件，更新列表与任务数量。
3. 用户从卡片打开详情，按权限编辑；执行者按有效租约更新执行状态。
4. 拖动与按钮提交相同业务动作，不跳过认领、证据或验收要求。

**异常与恢复**：两个浏览器同时编辑时后提交者收到版本冲突；Viewer 直接请求也不能写入；存在其他有效执行租约时提示占用。已完成任务由管理员重开，不能直接拖成进行中。

**验收**：Given 卡片已被他人更新，When 提交旧版本，Then 返回冲突且保留输入。Given 用户把卡片拖入已完成，Then 仍须满足人工接受条件。

关联：FR-05；S-01、S-02。

## UC-05 Agent 认领、续租与释放任务

**User Story**：作为获授权的 Agent，我希望确认任务的执行权，以便避免与另一个执行者重复认领。

**参与者与前提**：用户或绑定其身份的 Agent；项目活跃，有任务写入 scope。**触发**：尝试开始任务。

**主流程**：

1. 执行者读取任务和当前有效决策，提交认领请求。
2. 服务端原子检查状态、项目授权和租约，成功后返回租约标识、截止时间与新版本。
3. 任务显示进行中及实际执行者；执行者在需要时续租。
4. 主动释放时写入续作说明、清理租约，任务回到待办。

**异常与恢复**：竞争失败返回被占用；租约过期后不能凭旧标识续写；断线后续租失败，执行者报告失去协调授权并停止提交状态。管理员终止租约须记录原因，后续正常重新认领。

**验收**：Given 两个认领请求同时到达，Then 只有一个有效持有者。Given 旧租约过期且新执行者已认领，Then 旧执行者写入失败。任务租约不宣称锁定本机文件。

关联：FR-06、FR-15；S-01、S-07。

## UC-06 记录阻塞与替代决策

**User Story**：作为执行者，我希望把无法继续的原因交给项目成员处理，并在决定变化后获取有效版本。

**参与者与前提**：有写入权限的成员或 Agent。**触发**：依赖缺失或项目决定变化。

**主流程**：

1. 执行者提交任务阻塞原因，系统在同一事务中记录事件、设为阻塞并释放租约。
2. 成员查看阻塞，发布决策；替代旧决策时指定旧决策 ID。
3. 系统保留历史，当前决策列表呈现新的有效决定。
4. 条件解决后，执行者重新认领任务并继续。

**异常与恢复**：新旧决策不属于同一项目则拒绝；旧决策已被其他请求替代则提示冲突。仅发布一般阻塞消息且未关联任务时，不自动改任意任务状态。

**验收**：Given 两次并发替代同一旧决策，Then 不出现两条被自动接受的冲突继任决策。Given 无权项目的 ID，Then 不透露决策正文。

关联：FR-07；S-03。

## UC-07 导入已有成果

**User Story**：作为贡献者，我希望将已有报告、文件或链接纳入项目，以便其他成员能在 Hub 找到历史工作。

**参与者与前提**：有成果写入权限的成员；项目活跃。**触发**：选择“导入成果”。

**主流程**：

1. 用户选择 Markdown、文件或外部链接，填写标题和可选关联任务。
2. 用户补充原始作者与日期，未知字段保留未知；系统另记导入身份和时间。
3. 系统验证输入，将上传文件保存至受管存储，创建草稿。
4. 用户阅读草稿预览，确认后进入发布流程。

**异常与恢复**：文件超限或上传中断时给出原因，不生成已发布成果；链接只接受允许的协议，系统不自动请求用户输入的任意内网地址；无来源证据不擅自补写作者。

**验收**：Given 原文件随后移动，Then 已成功存储的授权副本仍可下载。Given 原始日期未知，Then 不把导入日期显示为原始日期。

关联：FR-09；S-04。

## UC-08 创建、发布和更新成果

**User Story**：作为贡献者或 Agent，我希望提交可阅读的工作结果，并保留版本，以便他人审阅和后续追溯。

**参与者与前提**：有成果写入权限的成员或 Agent；Agent 仅写 Markdown/链接。**触发**：产生阶段性结果。

**主流程**：

1. 操作者创建草稿，填写标题、正文/链接或上传文件及关联任务。
2. 系统把实际 Agent 身份和所属用户分别记录；草稿归所属用户管理。
3. 发布者选择项目可见；需要受限发布时管理员先设定成员名单，再发布。
4. 发布产生不可变版本和权限一致的活动事件。
5. 后续修改建立新工作草稿，再次发布生成下一版本，旧版本保留。

**异常与恢复**：发布失败保留草稿；重复提交返回相同版本；Contributor 不能编辑他人作品；草稿保密且不进入项目公共统计。限制名单尚未配置时不能短暂以项目可见发布。

**验收**：Given V1 已发布、V2 在编辑，Then Viewer 仍读 V1，不能读 V2。Given Agent 发布，Then 操作者显示 Agent，所属用户可追溯；发布本身不完成任务。

关联：FR-09、FR-10、FR-12；S-01、S-04、S-05。

## UC-09 提交任务、人工验收和重开

**User Story**：作为项目负责人，我希望依据明确成果或证据接受任务，以便完成状态有可核对的依据。

**参与者与前提**：有效持有者提交，Owner/Admin 人工验收；项目活跃。**触发**：执行者认为满足验收条件。

**主流程**：

1. 执行者提交完成说明和成果版本引用/文字证据。
2. 系统验证证据存在、属于本项目且当前可访问，记录本次提交，清理执行租约并进入待验收。
3. Owner/Admin 阅读验收条件、提交说明和绑定版本。
4. 接受时记录验收人和时间，进入已完成；退回时要求原因，回到待办。
5. 管理员后来发现问题可说明原因重开，保留此前接受历史。

**异常与恢复**：证据被删除或不可读时暂停验收并提示补充；版本已变化时刷新再操作；Agent 直接调用完成接口被拒绝。文字证据中可记录验证步骤，不能只填无意义占位符。

**验收**：Given Agent 提交，Then 状态是待验收且完成数未增加。Given Owner 接受 V1 后成果更新为 V2，Then 验收记录仍指向 V1。

关联：FR-13；S-01、S-05。

## UC-10 阅读、预览和下载成果

**User Story**：作为有权限的读者，我希望打开成果的真实内容和版本，以便直接利用已有工作。

**参与者与前提**：项目成员且满足成果可见性。**触发**：从成果列表、活动或任务打开成果。

**主流程**：

1. 系统重新验证当前权限，展示可访问版本和来源。
2. Markdown 安全渲染，允许的文件类型预览；其余类型显示元数据和下载入口。
3. 用户查看历史发布版本或下载指定文件。
4. 外部链接标记为外部，打开时由目标站点处理其自身授权。

**异常与恢复**：权限已被撤回时阻止下一次读取/下载；软删除成果不保留可绕过的文件地址；文件缺失说明不可用，不伪装成正常预览。

**验收**：Given 已复制附件 URL 的非成员，Then 下载仍被拒绝。Given 带脚本的内容，Then 预览不执行该脚本。

关联：FR-09、FR-10；S-04、S-05、S-06。

## UC-11 设置受限成果与删除

**User Story**：作为项目管理员，我希望控制特定成果的阅读范围，以便项目成员只看到被授权的内容。

**参与者与前提**：Owner/Admin；成果属于本项目。**触发**：调整可见性或删除成果。

**主流程**：

1. 管理员选择项目可见或受限，并在受限时选择当前项目成员。
2. 服务端保存新规则，历史版本、附件、活动及检索结果随之采用新权限。
3. 操作留下仅管理员可见的审计元数据。
4. 删除时确认对象，软删除成果并关闭普通读取入口。

**异常与恢复**：名单不能包含其他项目成员而绕过成员关系；并发修改时要求重新确认；已有任务验收引用不被悄悄改写，呈现材料已不可用。

**验收**：Given 成果由公开给项目改成受限，Then 非名单成员的下一次列表、搜索、活动及附件请求均不可见。已经下载的副本不能通过此操作撤回。

关联：FR-10、FR-11、FR-14；S-04、S-06。

## UC-12 邀请、改角色、移除成员与转移所有权

**User Story**：作为 Owner/Admin，我希望明确谁能参与和查看项目，以便协作范围可管理。

**参与者与前提**：项目 Owner/Admin；目标可为已有账户或受邀的新成员。**触发**：打开成员管理。

**主流程**：

1. 管理员指定接收者或选择可转交邀请方式、角色和期限，生成一次性邀请；界面明确链接授予范围。
2. 对方在自己的设备打开链接，注册或登录，以自己的身份接受，成员关系生效。
3. 管理员调整允许的角色或移除成员，服务端同步更新有效权限并处理不再有执行权的租约。
4. 转移所有权仅由 Owner 发起给已有成员；目标接受后事务内完成转移。

**异常与恢复**：过期、已使用、已撤回邀请均失效；绑定指定身份时不允许其他身份接受；未接受邀请不授予访问；Admin 不能操作 Owner 或给自己提权；不能直接移除唯一 Owner；移除成员不能删除其历史署名和审计记录。

**验收**：Given Contributor 降为 Viewer，Then 其 Agent 的后续写入失败。Given 成员被移除，Then 其已有浏览器会话与 Agent 请求均失去项目访问。Given 所有权转移，Then 任意时点恰有一个 Owner。

关联：FR-11、FR-14；S-06、S-08。

## UC-13 连接、检查与撤销 Agent

**User Story**：作为贡献者，我希望为指定客户端授权一个项目，并能撤销它，以便 Agent 有清晰的协作范围。

**参与者与前提**：Owner/Admin/Contributor；目标客户端是可检测和实测的版本。**触发**：在项目中添加 Agent 连接。

**主流程**：

1. 用户在自己的设备登录团队服务并授权设备，选择客户端、项目和操作 scope，预览配置差异。
2. 系统创建绑定用户/设备/项目的凭证并写入最小配置，核验服务地址和证书，展示客户端所需的重启或信任步骤。
3. 用户启动客户端，执行真实工具调用，Hub 才显示连接已验证。
4. 用户可撤销自己的连接；Owner/Admin 可撤销项目内连接。卸载只移除可归因的配置并撤销对应凭证。
5. 管理员从审计查看授权与撤销记录，凭证原文不显示在记录中。

**异常与恢复**：配置存在但未调用成功时显示待验证；客户端配置被用户改过时保留修改并报告差异；凭证不出现在普通日志或活动正文。

**验收**：Given MCP 传入别的项目 ID，Then 不能超出凭证 scope。Given 连接被撤销，Then 下一个工具调用拒绝。Given 重复安装/卸载，Then 不覆盖无关配置。

关联：FR-12、FR-14；S-01、S-08。

## UC-14 获取上下文并交接任务

**User Story**：作为接手的 Agent，我希望知道已经做了什么、下一步是什么和材料在哪里，以便继续同一任务。

**参与者与前提**：原执行者、接手者；项目授权有效。**触发**：会话结束或有人准备接手。

**主流程**：

1. 原执行者保存完成摘要、待办步骤、风险和成果/commit 引用。
2. 系统把交接记录关联任务并释放原租约，任务回到待办。
3. 接手者读取最新有效决策、未读事件和交接记录，按顺序确认已处理事件。
4. 接手者确认所需材料在当前工作副本可用，跨设备代码任务先完成 UC-19 校验，再重新认领。

**异常与恢复**：材料缺失时记录阻塞，不宣称已完成交接；事件超出上下文预算时分页，未返回事件不提前确认；远端正文内的命令仅作为不可信文本。

**验收**：Given 旧会话尚未释放且租约有效，Then 新会话不能认领。Given 第二页尚未读，Then 游标不跳过该页。断线重试允许按事件 ID 去重，不漏事件。

关联：FR-07、FR-08；S-03、S-07。

## UC-15 断线、重试与重启恢复

**User Story**：作为正在工作的用户，我希望服务暂时不可用时保留输入，并知道哪些动作已成功，以便安全继续。

**参与者与前提**：用户/Agent；服务中断或写入响应丢失。**触发**：刷新、上传、提交或续租失败。

**主流程**：

1. Hub 保留最后已知内容，显示断开与最后同步时间；用户输入保留为未提交内容。
2. 服务恢复后，客户端重新验证身份和权限，获取最新任务版本与读取游标。
3. 写入是否成功不明确时，以原请求标识重试或查询，返回原结果。
4. 服务正常重启后恢复已提交任务、成果、审计及读取进度；草稿恢复不得泄露给换登录的其他账户。

**异常与恢复**：中断期间过期的租约不能当作仍有效；权限已变时不自动重发写入；文件上传未完成时清理暂存并允许重新上传。

**验收**：Given 写入成功但响应丢失，When 重试，Then 不创建重复成果/任务/事件。Given 用户切换账户，Then 前一用户未提交的敏感正文不显示给新账户。

关联：FR-15；S-07。

## UC-16 归档、恢复与删除项目

**User Story**：作为项目负责人，我希望在阶段结束后保留历史并停止修改，以便项目列表保持清楚且成果可追溯。

**参与者与前提**：Owner/Admin 可归档恢复，Owner 可删除。**触发**：项目不再继续推进。

**主流程**：

1. 管理员确认归档，系统终止有效租约，将项目置为只读。
2. 项目从默认活跃列表移出，有权限成员可通过归档筛选阅读。
3. 管理员恢复项目后允许正常认领与写入，任务状态不被自动重排。
4. Owner 选择删除时另行确认，项目软删除并停止所有访问；恢复/永久删除由后续保留策略约束。

**异常与恢复**：归档后的 Agent 写入拒绝；恢复不能复活被撤销的凭证或被移除的成员；Viewer 直接请求不能归档。

**验收**：Given 归档请求与任务写入并发，Then 操作按一致顺序裁决，归档生效后的写入被拒绝。Given 恢复项目，Then 原有成果版本与验收历史仍在。

关联：FR-02、FR-11、FR-14；S-08。

## UC-17 部署团队服务并从独立设备访问

**User Story**：作为团队负责人，我希望成员从自己的电脑连接同一服务，以便分布协作不依赖某个开发会话一直开着。

**参与者与前提**：实例维护者、Owner、Contributor、Viewer；有可持续运行的主机及可达地址。**触发**：团队启用 CoAgents。

**主流程**：

1. 维护者部署服务，配置持久化数据和成果存储、HTTPS、可访问的外部地址以及备份/恢复流程。
2. 完成受保护的首次设置，Owner 创建项目并邀请成员。
3. 至少两台独立机器通过相同服务地址登录，登记设备，并各自连接实际 Agent 客户端。
4. 验证任务写入、事件、成果上传/下载和权限作用于同一个项目。
5. 分别在 LAN 和一种跨网络访问路径测试，记录机器、账号、客户端版本、网络拓扑和结果。

**异常与恢复**：地址不可达时提供连接诊断；证书错误时不自动跳过验证；服务重启后不丢失已提交成果；服务器不可达时不切换到另一个无共享状态的“成功”服务。

**验收**：三种角色、两台独立机器、两种 Agent 客户端跑通首版闭环。单机多标签或仅端口连通不能判定通过。

关联：FR-16；S-09。

## UC-18 实时同步、站内通知与断流补读

**User Story**：作为远程成员，我希望及时看到同伴的任务和成果变化，并收到与我有关的提醒，以便及时协作。

**参与者与前提**：已登录且有项目权限的 Hub/Connector；已建立事件通道。**触发**：他人提交任务变化、阻塞、成果或定向交接。

**主流程**：

1. 服务先持久化业务变更和事件，再向有权限的连接推送。
2. Hub 更新看板/活动；任务指派、阻塞、待验收和定向交接产生去重的站内通知。
3. Connector 保存收到的事件；Agent 真正读取后才更新已读状态，送达不能冒充已读。
4. 断流时显示连接状态，重连后重新授权并从确认游标补读，按事件 ID 去重。
5. 项目权限变化后停止向旧连接发送内容；降级轮询明确标记。

**异常与恢复**：推送先后与网络到达顺序不一致时按服务端序号补齐；通知目标无权读取对象时不推送其摘要；后台 Connector 收到提醒不自动启动 Agent。

**验收**：在 PRD 记录的网络条件下测量提交到另一设备显示的 P95 延迟；断流期间事件恢复后完整可读，通知不重复，撤权后旧流不再收到新内容。

关联：FR-18、FR-15；S-09、S-12。

## UC-19 跨设备检查代码并接手任务

**User Story**：作为另一台电脑上的接收者，我希望确认代码和成果已准备好，再接受交接，以免只有说明而没有可继续的工作副本。

**参与者与前提**：原执行者、目标接收者；都有项目权限及独立代码仓库访问权。**触发**：代码任务发起定向交接。

**主流程**：

1. 原执行者在用户选择的工作目录读取仓库身份、分支、commit 和未提交状态，说明需要交付的改动及关联成果版本。
2. 未交付的必要代码改动会阻止“可接手”确认；执行者通过团队既有 Git 方式交付代码，CoAgents 不把未提交文件默认为已经上传。
3. 接收者在自己的工作目录核对配置的仓库对应关系、指定 commit 的存在性及工作区是否具备安全继续的条件。
4. 条件满足后原子获取新租约并确认接手，记录双方用户、设备、检查结果及时间。
5. 非代码任务改为检查成果版本可读及交接说明，无需 Git 检查。

**异常与恢复**：无仓库权限、commit 缺失、工作区有冲突或必要修改未交付时保持待处理并说明原因；不自动覆盖文件、切换分支或执行远端正文中的命令；校验期间租约被他人获得则接手失败。

**验收**：先在接收端缺 commit 时确认被阻止，补齐后再确认成功；两台独立机器都保存检查证据。交接记录不等于代码传输，校验也不等于测试已经通过。

关联：FR-19、FR-08；S-07、S-09。

## UC-20 设置里程碑和截止日期

**User Story**：作为负责人，我希望围绕交付节点安排任务，并知道哪些事情逾期，以便对多人工作进行计划与验收。

**参与者与前提**：Owner/Admin 管理计划，成员按权限阅读并执行任务。**触发**：项目建立阶段性交付目标。

**主流程**：

1. 管理员创建里程碑，填写目标、验收条件、目标日期、关联任务；可设置项目和任务截止日期。
2. 系统按项目时区解释仅日期输入，保存确定的时刻，各设备按用户时区显示。
3. Hub 显示关联任务的各状态数量、阻塞、待验收和逾期；任务变化实时反映到里程碑。
4. 范围变化需记录增加/移除任务的原因；任务首版最多归属一个里程碑。
5. 管理员核对成果后确认达成并记录依据；仍有未完成任务时必须明确处理或调整范围。

**异常与恢复**：过了目标日期只标记逾期，不自动达成；空里程碑不显示 100%；角色不足无法修改目标或制造达成；并发调整要求版本检查。

**验收**：两个时区的设备对应同一截止时刻；看板与里程碑数量一致；范围变更及人工达成依据均可追溯。

关联：FR-20；S-10。

## UC-21 全文搜索成果并定位版本

**User Story**：作为项目成员，我希望用记得的正文关键词找到报告，以便复用已完成的工作。

**参与者与前提**：有权限的读者；项目已有发布成果。**触发**：在 Hub 输入关键词并选择项目/文件类型等筛选。

**主流程**：

1. 成果发布后对 Markdown、纯文本和有文本层的 PDF 提取正文，标记索引处理中/完成/失败/不支持。
2. 用户默认检索最新已发布版本；显式切换时可搜索仍有权限的历史版本。
3. 服务按当前成员关系和成果可见性返回结果、总数及片段，标出标题、版本、命中位置。
4. 点击结果进入指定版本和位置；PDF 提供命中页定位，不能内嵌预览时显示页码并提供授权下载。
5. 删除或权限变更立即作用于查询授权，即使旧索引尚在也不能返回无权内容。

**异常与恢复**：扫描件不冒充已完成正文索引；外部链接不自动抓正文；索引失败可重试且不阻断已授权文件阅读；缓存键不得让不同身份共享无权限片段。

**验收**：只出现在正文、不在标题摘要中的词可以命中三种支持格式；无权账户获得零泄露结果；旧版本命中明确标记版本，无法提取文件如实显示状态。

关联：FR-21；S-11。

## UC-22 撤销单设备并验证分布状态

**User Story**：作为设备所有者或项目管理员，我希望在设备丢失或结束使用时收回授权，同时让其他有效设备继续工作。

**参与者与前提**：同一用户至少两台授权设备，相关 Hub/Connector 连接正在使用。**触发**：用户撤销自己的设备，或管理员撤销该设备在项目中的授权。

**主流程**：

1. 操作者查看设备及关联会话，明确撤销自身设备全部授权，或只撤销指定项目范围。
2. 服务使对应设备会话和 Agent 凭证失效，终止相关推送连接，清理不再有效的执行租约。
3. 被撤销设备下次请求或重连被拒绝；其他未受影响设备继续正常使用。
4. 审计记录撤销范围、操作者和时间；需要恢复时重新进行设备授权，不复用撤销凭证。

**异常与恢复**：设备离线不影响服务端撤销生效；消息通道断开失败也必须在下一条事件投递前校验权限；项目 Admin 不能撤销设备对其他项目的授权。

**验收**：同时验证 API、MCP、已有事件流、全文检索和附件请求；撤销范围正确，其他设备仍可访问；已下载副本和不受控进程不纳入远程撤销承诺。

关联：FR-17、FR-18、FR-11；S-08、S-12。
