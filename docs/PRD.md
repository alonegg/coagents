# CoAgents 产品需求文档（PRD）

版本：0.2 · 日期：2026-09-23 · 状态：多人分布式首版需求基线；首版已实现，验收见 [验收记录](records/acceptance.md)。

本文件负责定义产品目标、范围、业务规则和验收要求。[使用场景](SCENARIOS.md)描述用户在什么情况下使用产品；[Use Cases](USE_CASES.md)描述具体操作及失败处理。实现方式见架构与接口草案。

## 1. 产品定义

CoAgents 是可自托管的多人、多设备、多 Agent 项目协作系统。团队成员在各自电脑上使用自己的编码客户端，通过同一协作服务共享任务、决策和成果。CoAgents Hub 为负责人、贡献者和审阅者提供统一的项目入口。多人分布使用是第一版必须验证的核心价值。

产品要让用户在一个入口回答四个问题：哪些项目正在推进，谁在处理什么，当前卡在哪里，已经产生哪些可查看的成果。每个回答都必须来自有来源的项目记录，并受访问权限约束。

“本地化”表示数据和服务由用户或团队自行部署管理，支持不同电脑、不同地点的成员连接到团队服务。第一版采用一个权威协作服务和多个客户端，不要求所有人处于同一局域网；可通过 LAN、VPN 或受保护的 HTTPS 地址访问。Agent 自身的模型调用由其所属客户端负责。

## 3. 用户与核心诉求

| 用户 | 日常问题 | 期望结果 |
| --- | --- | --- |
| 分布团队成员 | 每个人的 Agent 在不同电脑上工作，任务、上下文和结果互不相通 | 各用各的工具与账号，在同一项目协作，跨设备接手并核对成果。 |
| 独立开发者 | 同时开多个 Agent，反复解释上下文，容易重复做任务 | 用一个项目共享任务、决策和成果，同时保留各客户端的工作方式。 |
| 项目负责人 | 难以从聊天和文件夹判断项目是否推进 | 在 Hub 发现阻塞、待验收任务和新成果，并作出下一步安排。 |
| 项目贡献者 | 不清楚自己负责什么、别人做到了哪里 | 获得清晰任务与可访问材料，提交可追溯的成果和交接记录。 |
| 只读审阅者 | 需要看成果和进度，不应修改项目或看到草稿 | 在授权范围内阅读已发布成果和项目进度。 |
| 实例维护者 | 需要管理本地服务、账户和备份 | 维护服务可用性；实例维护身份与项目业务角色分开建模。 |

Agent 是绑定用户和项目的执行身份。Hub 应同时显示实际操作者与其所属用户，避免把 Agent 操作误记为人类亲自操作。

## 4. 目标与首版范围

首版目标是跑通“部署团队服务 → 邀请成员 → 各自电脑接入 Agent → 并行分工 → 实时共享活动 → 跨设备交接 → 提交与审阅成果 → 围绕里程碑继续协作”。必须用至少三个人类身份、两台独立机器和两种实测 Agent 客户端验收，不能用单机多窗口替代。单机使用是同一产品的兼容场景。

| 优先级 | 范围 |
| --- | --- |
| P0：协作核心 | 用户与成员、Hub、活动、Kanban、租约、决策/阻塞、成果阅读/导入/版本、权限与审计、两个客户端真实集成。 |
| P0：分布协作 | 自托管部署、远程登录、邀请注册、设备授权、实时通知、断线重连、跨设备 Git 交接检查。 |
| P0：进度与检索 | 里程碑、项目/任务截止日期、成果全文搜索及统一索引权限。 |
| 暂不纳入 | 模型推理代理、共享订阅、Agent 自动启动、任意远程执行、代码目录实时同步、公开匿名分享、企业 SSO。 |

不预设节省时间或降低冲突的百分比，待试用记录形成基线后评估。

建议首版验证规模为 10 位成员、20 台注册设备和 50 个并发 Agent 会话；这是待实测的容量目标。服务部署在团队可持续访问的主机、NAS 或服务器上，不依赖某位成员的电脑一直在线。第一版不要求多主写入、跨地域数据库复制或离线编辑自动合并。

## 5. 信息架构与关键页面

```text
登录 / 首次设置
└─ CoAgents Hub
   ├─ 我的项目：项目卡片、搜索、活跃/归档筛选
   ├─ 最近活动：跨项目、按类型/操作者筛选
   └─ 项目详情
      ├─ 概览：目标、里程碑、截止日期、任务分布、阻塞、待验收、最近成果
      ├─ Kanban：五列任务、任务详情与关联记录
      ├─ 活动：按时间查找变更、决策与交接
      ├─ 成果：列表、全文搜索、正文/预览、版本和来源
      └─ 设置：邀请、成员、设备、Agent 授权、归档及审计
```

卡片与时间线中的对象都能进入其详情；任务详情可到关联成果，成果可回到任务和发布事件。全文搜索覆盖已发布 Markdown、纯文本和可提取文字的 PDF；扫描件 OCR、外部链接正文抓取不作为首版格式支持要求。不能提取的文件显示明确状态，仍可检索元数据。搜索返回可见的匹配片段、来源版本和位置。

## 7. 任务与进度规则

任务包括标题、说明、验收条件、负责人、当前执行者、状态、租约、关联成果与活动。负责人用于责任归属，租约表示当前执行权，两者分别显示。任务租约只协调参与 CoAgents 的执行者，不保证其他进程不会修改同一文件。

| 状态 | 含义 | 进入和退出 |
| --- | --- | --- |
| 待办 | 已记录，尚未开始 | 认领后进入进行中。 |
| 进行中 | 正在推进 | 可提交待验收、报告阻塞或主动释放回待办。 |
| 阻塞 | 缺少条件无法推进 | 记录原因；条件解决后重新认领进入进行中。 |
| 待验收 | 已提交完成说明与成果/证据，等待人工检查 | Owner/Admin 接受为已完成，或退回待办并给出原因。 |
| 已完成 | 人工明确接受 | Owner/Admin 可说明原因后重开为待办。 |

提交待验收、进入阻塞、释放、完成与重开均清理当前执行租约。租约自然过期只改变租约提示，不自动移动卡片。Owner/Admin 可带原因终止租约，之后按正常流程重新认领；管理员不能通过普通拖动绕过有效租约。

本版建议任务都经过人工接受。单人项目中由同一用户完成该动作，Agent 只提交待验收。无独立文件的任务可附文字证据，例如验证结果、commit 或说明；链接本身不被当作已验证证据。完整证据应对项目成员可读，受限成果不自动复制到公开任务说明。

完成率为 `已完成任务数 / 五列可见任务总数`，同时显示分子分母。空任务集显示“暂无任务”。首版不增加取消列或任意列配置。Owner/Admin 管理里程碑及其验收条件、目标日期和关联任务；每张任务首版最多归属一个里程碑。项目、任务可设截止日期，UTC 保存并按用户时区展示；只有日期的输入按项目时区当天结束解释。Owner/Admin 确认里程碑达成时记录依据，存在未完成关联任务必须先明确调整范围并保留记录。逾期依据截止时间与未完成状态计算，不自动改变任务状态。

### 7.1 分布协作规则

服务端裁决租约、权限和事件顺序，客户端时钟不决定执行权。断网时保留草稿和已读缓存并标记过期，不能离线认领或报告服务端写入成功；重连先检查身份、任务版本与租约。认领/续租等过期请求不自动重放；对结果未知的普通写入使用原幂等 ID 查询或重试。

实时通道以已提交的持久化事件为依据，不单靠内存推送。重连从最后确认游标补读、按事件 ID 去重；权限变更后已有长连接必须终止或重新授权。通知分为任务指派、阻塞、待验收、定向交接和权限变化；站内通知不默认发邮件或调用系统通知。Connector 收到事件不代表空闲 Agent 已读取或自动开始工作，界面区分已到达与已读取。

跨设备 Git 交接记录配置的仓库身份、分支、commit、工作区未提交状态和相关成果。未提交代码不会随交接记录传输；代码任务必须明确交付所需修改。接收端只在用户选定的工作目录检查，缺少仓库访问或 commit 时提示补齐，不自动切分支、覆盖文件或执行消息中的命令；材料和工作区校验通过后再以新租约确认接手。非代码任务按成果版本校验，无需伪造 Git 前提。

## 8. 成果生命周期

一个成果可包含正文、一份文件或一个外部链接；多份材料建立多项成果并关联任务。成果“已发布”表示进入可见范围，不表示内容准确或任务已验收。成果发布与任务完成分别记录。

导入已有材料时保留声明的原始作者/原始日期，另记真实导入人和导入时间；未知来源字段显示“未知”，不伪造为导入信息。上传文件复制到受管存储，不能保存依赖操作者本机路径的下载链接。外部链接仍受目标系统权限约束，CoAgents 不代为授予目标站点访问权。

编辑已发布成果产生工作草稿，已发布版本继续可读，发布新版本后更新当前版本。草稿仅作者及项目 Owner/Admin 可见。已发布成果可选项目可见或受限名单；名单只包含当前项目成员，Owner/Admin 保留项目内管理访问。权限改变同时作用于历史版本、附件、活动和索引。

软删除后，普通读取、版本和下载入口关闭，管理员可见删除记录；恢复和永久删除的保留策略待明确。读取权限控制不提供对已经下载的副本的远程撤回。

## 9. 身份与权限

实例维护账户负责首次设置和账户生命周期；每个项目恰有一个 Owner。实例维护身份不会自动赋予 Hub 中所有项目的阅读权限。本地 OS 管理员有能力访问底层文件，应用权限只保证通过 CoAgents 界面的访问隔离。

| 操作 | Owner | Admin | Contributor | Viewer | Agent |
| --- | --- | --- | --- | --- | --- |
| 读普通项目内容 | 可 | 可 | 可 | 可 | 取所属用户权限与 scope 的交集 |
| 读草稿/受限成果 | 项目全部 | 项目全部 | 本人草稿/明确授权 | 明确授权的已发布成果 | 同上，且受所属用户当前角色约束 |
| 建任务、执行、提交待验收 | 可 | 可 | 可 | 不可 | 需写入 scope 和有效执行权 |
| 人工验收、退回、重开 | 可 | 可 | 不可 | 不可 | 不可 |
| 改成果 | 项目全部 | 项目全部 | 本人创建的成果 | 不可 | 需写入 scope，仅本人名下成果 |
| 设受限名单、管理成员 | 可 | 可，不能移除 Owner、提升他人为 Owner 或修改自己的权限 | 不可 | 不可 | 不可 |
| 创建/撤销自己的 Agent 连接 | 可 | 可 | 可 | 不可 | 不可 |
| 撤销项目全部 Agent 连接 | 可 | 可 | 不可 | 不可 | 不可 |
| 归档/恢复 | 可 | 可 | 不可 | 不可 | 不可 |
| 转移所有权、删除项目 | 可 | 不可 | 不可 | 不可 | 不可 |

实例维护者在后台审批注册申请、停用/启用账户、发放临时密码和任命维护者；后台只显示项目元数据，不授予项目内容阅读权。管理员可邀请已有账户或生成一次性、有限期的项目邀请链接。邀请可绑定指定账户或接收者标识；如采用可转交链接，界面必须说明持有者可申请加入。新成员凭有效邀请完成注册/登录并明确接受后才获得设定角色；自助申请的账户须经维护者批准才能登录，且开通后不属于任何项目。链接由用户自行发送，系统首版不自动发邮件。每台设备经用户登录授权，Agent 凭证进一步绑定设备、项目和 scope；撤销设备使其浏览器/Connector 授权失效。转移所有权要求目标是现有成员并明确接受；事务内保持恰好一个 Owner。删除项目与归档分开，首版软删除。

任务标题、描述、决策和普通事件为项目共享内容；首版只对成果提供更细权限。受限信息不得从成果自动摘录到共享任务或事件。成员移除、降级、凭证撤销、项目归档后，后续请求按最新授权判断。尚未完成的租约被撤销或标记不可再用。

## 10. 界面反馈与异常

| 状态 | 用户应看到的反馈 |
| --- | --- |
| 无项目/无任务/无成果 | 显示原因与当前身份可执行的下一步；Viewer 不出现写入入口。 |
| 加载或刷新 | 保留已有内容并标记同步状态，不把加载失败显示成零任务。 |
| 服务断开 | 显示“连接中断”与最后同步时间；未提交正文保留，恢复后可重试。 |
| 更新冲突 | 显示任务已被他人修改，刷新后可重新操作；保留用户输入。 |
| 无权限或资源不存在 | 对非成员统一给出不可访问提示，不泄露资源标题或是否存在。 |
| 上传失败/格式无法预览 | 明确失败原因及允许范围；不产生可见半成品；不能预览时至少显示名称、大小、类型并提供授权下载。 |
| 归档项目 | 标记只读并解释需要恢复项目后才能继续工作。 |

首版提供实时业务事件通道和站内通知；在记录测试环境、在线连接稳定且网络 RTT 不超过 100ms 的条件下，事件提交到另一客户端显示的拟议目标为 P95 不超过 2 秒。断流后自动重连并补读，降级轮询时明确显示连接状态和同步时间，手动刷新始终可用。所有拖动操作提供按钮等价操作，关键状态以文字表达。

## 11. 数据、可靠性与发布要求

- 任务变更和对应事件在同一事务完成；创建/提交的重试使用幂等标识，避免重复任务和成果。
- 状态、已发布成果及读取进度在正常重启后保持；提供文档化的停止服务后备份/恢复流程，覆盖数据库和成果文件。
- 同伴文本和上传内容都视为不可信数据。Markdown 渲染清理脚本与危险链接，文件预览不能执行上传文件中的脚本。
- 权限检查覆盖 API、MCP、附件、搜索、统计和缓存；不把管理员专用审计元数据混入普通活动流。
- 远程访问使用 HTTPS；提供受支持的 LAN 与跨网络部署说明、受信任证书配置、服务地址和设备登记流程。客户端不默认忽略证书验证，不把本机初始化凭证暴露为公共注册入口。
- 撤权不仅作用于新请求，也作用于事件通道、站内通知、搜索结果和文件请求；离线设备本地已经保存的副本不宣称可以远程收回。
- UI、日志、包、安装路径、生成配置和产物使用 CoAgents 标识；参考归档不进入产品构建。
- 性能暂定验收基线：在记录服务器、客户端和网络配置的团队环境中，以 20 个项目、每项目 200 个任务和 1 万事件，结合 10 位成员、20 台注册设备及 50 个并发 Agent 会话测试；常规列表/看板读取 P95 不超过 2 秒（不含文件传输，稳定连接 RTT 不超过 100ms）。这是拟议门槛，需实现后测量。

## 13. 发布验收与待决定项

发布需跑通 [Use Cases](USE_CASES.md) 中全部首版主路径及失败路径。必须使用至少 Owner、Contributor、Viewer 三个真实账户、两台独立机器和两种 Agent 客户端，完成邀请 → 并行认领 → 实时活动 → Git 交接 → 成果提交/检索 → 人工验收 → 里程碑确认。还要注入断网、服务重启、时钟偏差、响应丢失和在线撤权，记录结果。验证 LAN 及一种跨网络部署路径；不以同机浏览器多标签模拟替代跨机验收。
